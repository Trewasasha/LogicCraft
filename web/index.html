Назначение и актуальность

LogicCraft устраняет разрыв между проектированием архитектуры и непосредственной реализацией, автоматически трансформируя визуальные абстракции в чистый объектно-ориентированный код.

01

Интерактивный холст

Разработка графического окна на базе PyQt6 `QGraphicsScene` с поддержкой сетки, панорамирования и drag-and-drop элементов.

02

Валидация данных

Контроль целостности схемы данных "на лету" с помощью Pydantic. Защита от дублирования имён и незаполненных интерфейсов.

03

Шаблонный движок

Генерация полноценного исходного ООП-кода (Python/Java) на основе метаданных с помощью гибких шаблонов Jinja2.

04

Undo/Redo и Слои

Реализация паттерна Command для отмены/повтора действий и независимый экспорт готовой MVC структуры проекта на диск.

Слой представления / View

Проектирование UMLNode и связей

Визуальные компоненты карт поддерживают строгое разграничение типов элементов: `class`, `interface`, `enum` и абстрактный класс. Система соединений обрабатывает анкерные точки на сторонах карточек, высчитывая геометрию стрелок для наследования, композиции, агрегации и реализации.

Поддерживаемые сущности:
• UMLNode (Позиционирование и метаданные полей/методов)
• UMLConnection (Связывание по строковым ID через анкеры)
Бизнес-логика / Services

Контроль циклов и трансляция

Специализированный слой сервисов (`Service Layer`) гарантирует валидность структуры перед генерацией. Применяется встроенный алгоритмический анализ для предотвращения сбоев в результирующих исходных кодах.

// Алгоритм предотвращения зацикливания

Services / CodeGenerator

Механизм трансляции UML в исходный код

Техническое обоснование автоматизации кодогенерации на основе метаданных модели

JSON Graph

Сериализация графа диаграммы из UMLDiagram в структурированные метаданные. Метод _build_inheritance_map строит карту наследования классов.

02. Маппинг полиморфных типов

Type Mapping

Компонент LANGUAGE_CONFIGS подменяет абстрактные сущности (string, list) на строгие примитивы конкретных целевых платформ.

Слияние очищенных метаданных со строгими файлами шаблонов (python_class.j2 / java_class.j2) и выгрузка готовых файлов.

Архитектурная декомпозиция комплекса

Обеспечение слабой связанности (Loose Coupling) через механизм сигналов и слотов PyQt6.

Слой 1

Model (Модель)

Изолированное хранилище состояния предметной области (`UMLDiagram`, `UMLNode`). Полностью независимо от графического интерфейса.

Слой 2

View (Представление)

Визуализация данных на базе компонентов `QGraphicsScene` и `UMLCard`. Подписывается на сигналы изменений и отображает UI.

Слой 3

Controller (Контроллер)

Связующее звено (`DiagramController`). Обрабатывает сигналы пользовательского ввода из View и обновляет состояние Model.

Слой 4

Services (Сервисы)

Выделенная сложная логика: генератор кода `code_generator.py`, сервис истории действий и менеджер сериализации.

Реализованный технологический стек

Python 3.x PyQt6 (GUI Engine) Pydantic (Validation) Jinja2 (Templates Engine) Pytest / PyInstaller
